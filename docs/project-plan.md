# Warp 安卓原生终端项目计划

## 图形标签扩展

Android 会话服务持有 TAWC 合成器和每个 Linux 主窗口的标签状态。Bash 与应用列表共用 tawcroot 的 Wayland 和 X11 套接字绑定。Android 端只为当前图形标签绑定 `SurfaceView`。TAWC 保留窗口与弹窗，并通过原生回调通知 Android 新建、更新和移除标签。

图形程序和字体通过 Debian APT 单独安装。图形入口和终端共用 `/home/warp`。图形示例用 Mousepad 验证 Wayland 文本输入与文件保存，用 xeyes 验证 XWayland 指针和 Bash 前后台启动。

## 首版交付

提供可侧载的 ARM64 Android 10+ APK、完整构建入口、固定上游版本、许可证和设备验收记录。用户首次联网初始化 Debian，之后离线打开两个 Bash 标签，运行命令或全屏编辑器，导入脚本并导出结果。

## 模块与数据

| 模块 | 职责 |
|---|---|
| `android/app` | Kotlin 与 Jetpack Compose 界面、安装和会话生命周期、终端输入、Android 文件选择器 |
| `backend` | GNU/Linux ARM64 程序，持有 Bash、真实 PTY 和 Warp 解析器 |
| `upstream` | Warp、TAWC 的固定提交号、来源与许可证说明 |
| `scripts` | 环境检查、依赖准备、打包和测试 |
| `docs` | 协议、阶段验收与验证记录 |

tawcroot 随 APK 安装至 Android 原生库目录，启动 Debian 内的后端。安装器在临时目录验证并展开 rootfs，执行 Bash 握手自检，再提交环境。失败后保留可重试的下载，用户主目录独立挂载为 `/home/warp`。

每个标签运行一个后端及一个 Bash PTY。后端通过 Warp 的 Bash 事件标记命令开始、结束与提示符，经版本化标准输入输出帧与 Android 通信。Android 服务保留会话，界面重连时读取当前状态。全屏应用使用终端网格。文件输入输出使用系统文件选择器和流式复制。

## 接口与恢复

- 固定依赖的两种构建目标分别为 Android `arm64-v8a` 的 tawcroot，以及 Debian `aarch64-unknown-linux-gnu` 的 Warp 后端。APK 包含两份二进制及默认安装镜像的 SHA-256。Debian 的初次下载和 apt 安装发生在设备上。
- 安装进度报告下载、校验、解包、软件包和 Bash 自检。下载支持 HTTP Range，校验失败时清除该归档。只有校验和解包均完成才记录暂存状态，软件包安装重试可复用该目录。活动 rootfs 与用户主目录分别保存，最后通过目录重命名提交。
- 后端每次启动生成 Warp shell 会话标识。应用经过版本握手，读取 Bash 的提示符结束标记后启用输入。跨端消息定义见 [终端协议](protocol.md)。
- 命令块保留最近 100 条，每块限制为 64 KiB 文本。原始终端流交给 VT 网格处理应用模式、颜色和光标。后台服务覆盖最多八个独立标签，标签显式关闭时回收其 PTY。
- 文件选择以打开的目录描述符定位路径，选定的导出目标必须是普通文件。导入使用独占创建，同名时追加编号。取消时清理本次产生的不完整文件。

## 阶段与验收

| 阶段 | 验收 |
|---|---|
| 0．建立工程 | 锁定上游，环境检查识别工具和设备，干净构建生成 APK |
| 1．真实终端 | ARM64 手机收到 `printf '你好\n'` 与 `false` 的独立命令块和退出码，`Ctrl+C` 可中断 `sleep` |
| 2．安装恢复 | 下载中断、校验失败和解包中止均可恢复，飞行模式下仍可启动，APK 升级后主目录文件哈希一致 |
| 3．手机交互 | 两个标签各自保留 Bash 状态，中文可一次提交，`vim` 可保存，横竖屏、软键盘和应用切换后接续会话 |
| 4．文件交换 | 中文文件名与二进制文件往返时 SHA-256 一致，重名保留两份，取消后清除临时文件 |
| 5．打包交付 | 验证 APK 签名及 SHA-256，提供构建说明、实测机型和验收记录 |

主机优先检查真实 PTY 与 Warp 事件链路、帧分片、安装失败恢复和文件名约束。Android 真机用于验证 tawcroot、软键盘、后台生命周期及系统文件选择器。
